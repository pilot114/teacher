# topics

Конспекты, расписание и тесты. Vue 3 + vue-cli, собирается в статику и лежит на GitHub Pages.

## Разработка

```sh
yarn install
yarn serve
```

Прогресс по тестам хранится на сервере (`../backend`), поэтому приложение начинается с формы входа.
Поднимите бэкенд рядом:

```sh
cd ../backend && go build -o teacher-api . && ./teacher-api user add masha "Маша" && ./teacher-api
```

В разработке фронт по умолчанию ходит на `http://localhost:8090` — это адрес бэкенда из коробки.

## Сборка

```sh
yarn build
```

Адрес API берётся из `VUE_APP_API_URL`. Для боевой сборки положите его в `.env.production.local`:

```
VUE_APP_API_URL=https://api.example.org
```

Если переменной нет, фронт ходит на тот же домен, откуда отдан, — годится, когда API проксируется
рядом со статикой. Страница на GitHub Pages отдаётся по HTTPS, так что и API должен быть за HTTPS.

## Что где лежит

- `src/auth.js` — вход, токен, выход
- `src/api.js` — обёртка над fetch и адрес API
- `src/progress.js` — прогресс по тестам: копия на время сессии; пишет его только сервер по итогам попыток
- `src/history.js` — история ученика: отметки об открытии тем и тестов и о начале практики (кнопка «Начать»), чтение ленты
  и попыток; страница — `src/views/StudentHistory.vue`, разбор попыток — `src/views/TestAttempts.vue`
- `src/sections.js` — разделы меню; у «Истории» свой адрес `/history`
- `src/tests.js` — тесты через API: оглавление, начало попытки, отправка ответов. Банка и правильных ответов
  во фронте нет — они в `backend/tests/`, проверяет ответы сервер (`backend/bank.go`)
- `src/viewport.js` — общий брейкпоинт мобильной вёрстки (900px); те же 900px стоят в media-запросах
  компонентов, так что менять ширину нужно в обоих местах
- `data/` — конспекты и расписание по классам; всё отсюда публикуется на GitHub Pages, поэтому тестов здесь нет

## История

Страница `/history` показывает ленту действий вошедшего ученика и разбор каждой попытки теста.
Правильные ответы в разборе открываются по тем же правилам, что и в самом тесте: когда тест сдан
или попытки закончились.

У GitHub Pages нет отдачи приложения на произвольный путь, поэтому сборка кладёт копию `index.html`
в `404.html` — так прямая ссылка на `/teacher/history` открывает приложение.

## Проверка ответов со свободным вводом

Ответы проверяет сервер (`backend/bank.go`), фронт только отправляет их.

- **Математика** (`exactSubjects` в `backend/bank.go`) — строгая сверка с эталоном.
- **Остальные предметы** — ответ и эталон сначала нормализуются: регистр, пробелы, `ё`→`е`, знаки
  препинания по краям, сербская латиница → кириллица. Если всё равно не совпало, сервер отдаёт ответ
  арбитру — Claude Haiku (см. `backend/README.md`). Пока тот решает, тест показывает «Проверяю…».
- **Вопросы на одну конкретную форму** (футур II, падеж, предлог, множественное число…) помечены в банке
  `judge: false` и проверяются только по эталону: сербскую грамматику Haiku знает плохо и засчитывает
  чужие формы. Новым вопросам такого рода ставьте `judge: false`. Обратное тоже можно: `judge: true`
  отдаёт арбитру вопрос даже по математике.

Причину, по которой арбитр засчитал ответ, ученик видит сразу. Причину отказа — только когда тест
закрыт (сдан или попытки кончились), как и правильные ответы: иначе она могла бы подсказать.

## Старый прогресс из браузера

До бэкенда результаты лежали в `localStorage` под ключами `teacher.test.<предмет>|<тема>`, и при входе
они переносились на сервер. Перенос убран: через него можно было записать себе зачёт, не сдавая тест.
Итог теста теперь пишет только сервер по результатам попыток.
